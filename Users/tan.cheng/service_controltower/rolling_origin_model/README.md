# Rolling-Origin Machine Risk Model

This package contains the complete model-development workflow and the production scoring workflow. It intentionally excludes test-only, output-validation, and documentation-generation scripts.

## Required folder layout

```text
project_root/
  enriched_data/
    fault_codes.csv
    fluid_samples.csv
    maintenance.csv
    operation.csv
    Physical Failure Events.csv
    warranty.csv                  # required only when TARGET_SOURCE="warranty"
  incoming_data/
    fault_codes.csv
    fluid_samples.csv
    maintenance.csv
    operation.csv
    Physical Failure Events.csv  # optional according to config.py
  rolling_origin_model/
    config.py
    run_development.py
    00_prepare_operation_data.py
    ...
```

## Development and retraining workflow

Run all enabled stages:

```bash
python run_development.py
```

Execution order:

1. `00_prepare_operation_data.py` - clean the operation extract and build the machine roster.
2. `01_build_snapshot_dataset.py` - build monthly leakage-safe training snapshots.
3. `02_tune_xgboost.py` - optionally tune L1, L2, and early stopping.
4. `03_rolling_origin_validation.py` - evaluate algorithms and feature variants on forward folds.
5. `04_calibrate_probabilities.py` - fit and evaluate fold-specific Platt calibration.
6. `05_select_operating_threshold.py` - select the configured F1 or F2 operating threshold.
7. `06_multi_anchor_validation.py` - score complete anchor fleets and save Top-N statistics.
8. `07_build_tier_policy.py` - select Critical, High, and Medium boundaries with confidence intervals.
9. `08_train_final_model.py` - fit the final model, calibration, tier gates, feature importance, SHAP, and learning curves.
10. `09_export_production_settings.py` - export reviewed model and tier values for the approved section of `config.py`.

The stage controls and all model, calibration, threshold, and tier parameters are in `config.py`.

## Production deployment workflow

Place the latest three months of source files in `incoming_data`, then run:

```bash
python 10_score_new_data.py --score-date YYYY-MM-DD
```

The deployment stage:

- validates and combines the incoming files with retained long-term history where required;
- builds one snapshot for every eligible machine;
- predicts the raw XGBoost probability;
- applies the approved Platt calibration;
- calculates `risk_index = calibrated probability x 100`;
- assigns provisional Top-N tiers;
- applies the approved tier score gates and demotion logic; and
- saves machine scores, final tiers, source manifests, and summary counts.

## Production release control

`config.py` contains the approved `PRODUCTION_MODEL_SETTINGS`, selected fault codes, and `PRODUCTION_TIER_POLICY`. After retraining, review the validation results and the file generated by `09_export_production_settings.py` before replacing the approved values.
